# MusicDB Mobile

Мобільний застосунок (Expo / React Native) для тієї самої бази даних музичних
композицій, що й веб-версія MusicDB. Той самий стиль (кольори, шрифти
Playfair Display + DM Mono), той самий бекенд (`MusicDB.Api`) — просто
мобільний клієнт до нього.

## Що реалізовано

- Бібліотека композицій: пошук, фільтр за жанром, перемішування, статистика.
- Відтворення через YouTube (прихований WebView-плеєр) з міні-баром знизу:
  play/pause/prev/next, seek, shuffle/repeat, кнопка "показати відео"
  (розгортає той самий плеєр у маленьку картку з реальним відео).
- Вхід через Google (той самий бекенд-флоу, що й у вебі).
- Запит на додавання пісні + автозаповнення з iTunes, підбір жанрів.
- Профіль: аватар, нікнейм, статистика, улюблені жанри, улюблені пісні,
  плейлисти (створення, перегляд, "слухати весь плейлист", видалення пісні).
- Рекомендації (ШІ) для авторизованих користувачів.
- Адмін: перегляд/редагування/підтвердження/відхилення заявок, форма
  прямого додавання пісні, об'єднання дублікатів жанрів.
- Перемикач мови (укр/eng) і теми (темна/світла) — ті самі значення, що й у
  вебі, зберігаються на пристрої.

## Запуск

```bash
npm install
npx expo start
```

Відкрийте застосунок у **Expo Go** (Android/iOS) відскануванням QR-коду, або
запустіть у симуляторі/емуляторі.

При першому запуску застосунок попросить **адресу сервера MusicDB** — це та
сама адреса, на якій працює `MusicDB.Api` (бекенд) для веб-версії, наприклад
`https://your-domain.com` або `http://192.168.x.x:5000` (якщо бекенд і
телефон в одній Wi-Fi мережі). Адресу можна пізніше змінити в Профілі
("Змінити сервер").

Бекенд змінювати НЕ потрібно — мобільний застосунок працює з тим самим API,
контролерами й базою, що й веб-версія.

## Технічні нюанси (варто знати)

- **Автентифікація.** Бекенд авторизує через Google OAuth + cookie-сесію
  (`MusicDB.Session`), як і у вебі. Мобільний застосунок не має системного
  браузера для цього флоу, тож вхід відкривається у вбудованому WebView на
  `/auth/login`, а всі подальші запити до API йдуть через прихований WebView,
  що завантажує `{сервер}/` (той самий origin → ті самі cookie). Це дозволяє
  повністю уникнути кастомних native-модулів (усе працює в Expo Go).
  Зворотний бік: Google іноді блокує вхід із вбудованих WebView
  повідомленням "This browser or app may not be secure" — застосунок підміняє
  User-Agent на звичайний Chrome, що зазвичай вирішує проблему, але Google
  може посилити перевірку в майбутньому. Якщо вхід не вдається — спробуйте
  ще раз; якщо проблема стійка, найнадійніший довгостроковий фікс —
  додати на бекенді окремий мобільний флоу автентифікації (напр. видачу
  JWT/API-ключа замість cookie), але це вже зміна бекенду.
- **Відео/аудіо у фоні.** Як і у вебі, звук іде через прихований YouTube
  iframe-плеєр. Поки застосунок активний і відкритий — відтворення працює
  стабільно. Повноцінне відтворення з вимкненим екраном/у фоні (як у
  Spotify) YouTube-embed у WebView не гарантує на всіх пристроях — це
  обмеження платформи, а не помилка застосунку.
- **Дата релізу / тривалість** вводяться текстом у форматах `РРРР-ММ-ДД` та
  `гг:хх:сс` (як у вебі) — без нативного календаря, щоб не тягнути додаткові
  залежності.

## Структура проєкту

```
src/
  api/          — типи, WebView-бридж до бекенду, типізовані ендпоінти
  player/        — YouTube-плеєр (WebView) + міні-плеєр бар
  state/         — налаштування (сервер/тема/мова), улюблені
  components/    — переюзабельні UI-елементи, іконки (ті самі SVG, що й у вебі)
  screens/        — екран налаштувань сервера
  constants/      — кольори/шрифти/i18n (перенесено з index.html веб-версії)
  app/            — маршрути expo-router (вкладки: Бібліотека, Запит,
                    Рекомендації, Профіль(+Плейлист), Адмін)
```
