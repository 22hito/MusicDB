# Веб-фронтенд (`wwwroot`)

Чистий HTML/CSS/JavaScript без фреймворку, збирача й npm-залежностей у продакшн-коді.

```
wwwroot/
  index.html          розмітка всіх сторінок (div#page-*) і модальних вікон
  css/                стилі — 11 файлів, порядок = каскад
  js/                 логіка — 27 модулів за функціями (+ vendor/signalr.min.js)
  mobile-player.html  сторінка-плеєр для WebView мобільного застосунку
  popout.html         окреме вікно відео (десктоп)
  manifest.json, sw.js, robots.txt, sitemap.xml, images/
```

## JS-модулі

Звичайні `<script>` (не ES-модулі): верхньорівневі `function`/`let`/`const` спільні для всіх файлів, а функції
викликаються ще й з `onclick="…"` у розмітці. Тому **порядок у `index.html` важливий**.

**Як віддається на проді.** Прод працює по HTTP/1.1 (6 з'єднань на сайт), тож `StaticAssetVersions` склеює
всі стилі `<head>` в один `/css/bundle.css`, а всі `<script defer>` — в один `/js/bundle.js` у тому самому
порядку (локально — окремі файли, увімкнути як на проді: `StaticAssets__Bundle=true`). Склеєний файл поводиться
інакше за окремі в трьох випадках — однакове верхньорівневе ім'я у двох файлах, звернення під час завантаження
файлу до імен із пізніших файлів, присвоєння імені, яке пізніший файл оголошує функцією. Їх ловить
`tools/check-bundle.cjs` у `npm run lint` (і в CI). Чужий код із `js/vendor/` загортається у власну функцію.

**Що відкладено.** Скрипт YouTube IFrame API (`_loadYtApi`) і сам плеєр (`_warmYtPlayer`) — не з `<head>`, а коли сайт
уже намальовано й браузер вільний (вбудований плеєр — ~1 МБ скриптів YouTube); із Save-Data — перед першим відтворенням. Каталог (`/api/songs?format=cols`) браузер починає
вантажити ще з `<link rel="preload">`, паралельно зі скриптами; `initApp()` бере саме цю відповідь.
До кінця `initApp()` (`appReady`) зміна мови/теми не перемальовує таблицю й статистику — це робить сам `initApp()`.

| Модуль | Відповідає за |
|---|---|
| `i18n.js` | Переклади uk/en і `t()` — підключається першим |
| `navigation.js` | Випадні меню, `showPage()`, мобільний таббар і пошук, маршрутизація (History API) |
| `helpers.js` | Дрібні утиліти (`esc()`, аватар-ініціали) і час: API віддає UTC, `fmtTime()` / `timeHtml()` показують його в часовому поясі глядача (`Intl.DateTimeFormat`), `dayGroupLabel()` — групи «Сьогодні / Вчора / …» |
| `songs.js` | Таблиці пісень (каталог і ком'юніті), фільтри, улюблені, об'єднання жанрів |
| `profile.js` | Власний профіль, плейлисти; спільні модалки (`confirmModal`, `_closeModalAnimated`) |
| `recommendations.js`, `wheel.js`, `stats.js`, `top.js` | Рекомендації, колесо фортуни, картки статистики, Топ 100 |
| `forms.js` | Заявки на пісні, автозаповнення з iTunes, редагування заявки й пісні |
| `appearance.js` | Теми, колір обкладинки в інтерфейсі, налаштування (`PREFS`) |
| `auth.js` | `initApp()`, `currentUser`, шапка, дзвіночок сповіщень |
| `player.js` | Плеєр (YouTube і файли), Media Session, відео-попап, караоке, біжучий рядок |
| `queue.js` | Черга: "Моя черга" (грає першою), "Далі", нещодавно прослухані, пошук; shuffle перемішує список наперед |
| `battle.js`, `artists.js`, `friends.js`, `graph.js` | Батл рояль (плейлист або жанр), сторінка виконавця, друзі й публічні профілі, граф схожості (`<canvas>`) |
| `taste.js` | «Схожий смак»: список найсхожіших людей і графи (люди; люди + виконавці) на спільному `graph.js` |
| `media-viewer.js` | Переглядач вкладень особистих повідомлень на сайті: фото (наближення, гортання, свайпи, клавіатура), відео, PDF, текст |
| `bug-reports.js`, `corrections.js`, `chat.js`, `ratings.js`, `nav-search.js` | Баг-репорти, запити на правку (форма, «мої запити», вкладка адмінки), спілкування, оцінки, глобальний пошук |
| `realtime.js` | SignalR: живі оновлення |
| `main.js` | Запуск застосунку — підключається **останнім** |

**Новий модуль:** створити `wwwroot/js/<назва>.js` і додати `<script src="/js/<назва>.js">` в `index.html`
перед `main.js`. Код, що виконується одразу при завантаженні (не всередині функцій), може звертатися лише до
модулів, підключених раніше.

**Лінт:** `npm run lint`. Конфіг `eslint.config.js` сам збирає верхньорівневі імена всіх модулів і передає їх
кожному файлу як глобальні, тож `no-undef` ловить справжні опечатки й між файлами.

## CSS-шари

| Файл | Вміст |
|---|---|
| `base.css` | Дизайн-система «Nocturne»: токени кольорів (oklch), теми, типографіка, навбар, сплеш |
| `components.css` | Таблиці, статистика, форми, рекомендації, колесо, батл, граф |
| `player.css` | Плеєр-бар, відео-попап, караоке |
| `layout.css` | Навігація, перемикачі, таблиця_2, сповіщення, оцінки, спілкування |
| `nocturne.css` | Фірмовий шар редизайну, «аврора», налаштування, адаптив під монітори |
| `overlays.css` | Модальні вікна, тости, баг-репорти |
| `responsive.css` | Масштаб браузера, телефон (≤768px) |
| `features.css` | Новіші функції (скріншоти, біжучий рядок, вікно підтвердження тощо) |
| `mobile-app.css` | Вигляд мобільного застосунку на телефоні: таббар, картки пісень |
| `polish.css` | Останній шар: дотик (ефекти наведення лише для миші, відгук на натискання, поля ≥16px на телефоні, безпечні зони), фокус, сильніші криві руху; сповіщення з вкладками, обговорення, пошук у дискографії, «Уся історія», колесо й графи на телефоні, налаштування й адмінка плитками |

Нові стилі — у відповідний шар; якщо вони мають перебивати старі, то в шар, що підключається пізніше.

## Інтерфейс

- **Маршрутизація:** кожна сторінка має власну адресу (`/top`, `/wheel`, `/chat/friends`, `/artist/{id}`, `/explore`…);
  `showPage()` ставить `data-page` на `<html>` — за ним CSS підсвічує активну вкладку. Старі адреси `/friends`
  і `/profile/settings` відкривають вкладку «Друзі» спілкування і профіль.
- **Спілкування:** вкладки Обговорення · Друзі · Особисті, в «Особистих» — підвкладки Чати / Запити. У гілці — відповідь
  на конкретний допис (цитата, сповіщення автору), «Стежити», поле відповіді закріплене внизу (Ctrl+Enter).
- **Сповіщення (дзвіночок):** вкладки «Загальні» (адмін, друзі, виконавці) і «Обговорення» (нові дописи в гілках,
  де ви писали, — з відповіддю просто зі сповіщення).
- **Графи:** колір — тотожність (основний жанр, тип зв'язку, роль), а не номер вузла; три слоти палітри перевірені
  `validate_palette.js` (скіл dataviz) для обох тем, решта — «інші»; легенда під графом. Радіальні графи вписуються
  разом із підписами; на телефоні — на весь екран, щипок для зуму, дотик спершу показує вузол, другий — відкриває.
- **Теми:** темна, сіра, світла, системна; 6 акцентних кольорів (відтінок `--ah`); налаштування інтерфейсу.
- **Телефон (≤768px):** той самий вигляд, що й у мобільному застосунку — шапка (пошук, дзвіночок сповіщень
  аркушем на всю ширину, аватар → профіль), таббар Бібліотека · Топ · Спілкування · Цікаве · Налаштування · Адмін,
  компактні картки пісень (комірка `td-mmeta` лише для телефону, клас `.m-only`), сортування списком,
  плаваючий плеєр над таббаром. Зміни мобільного вигляду переносяться і в застосунок.
- **PWA:** `sw.js` потрібен лише для встановлюваності й нічого не кешує. Обробник `fetch` навмисно порожній —
  Chrome тоді не будить SW на кожен запит сторінки (перехоплення через `respondWith` ламало аудіо й картинки з R2:
  CSP `connect-src`).
